# 2.3 注释

程序不仅要让机器执行，也要让人读懂。真正需要长期维护的代码，通常都离不开合适的注释。

注释不会参与程序运行，编译器也会忽略它们，但注释对程序员非常重要。它们的价值不在于“把代码翻译成中文”，而在于补充代码本身没有直接表达出来的信息。

## 为什么需要注释

很多初学者一开始会觉得：“代码都写出来了，为什么还要注释？”原因很简单，因为代码只能直接表达“做什么”，但不一定能完整表达“为什么这么做”。

例如，下面这行代码本身并不难懂：

```rust
let timeout = 30;
```

但如果没有上下文，别人并不知道：

- 这个 `30` 是 30 秒、30 毫秒，还是 30 次重试？
- 为什么是 30，而不是 10 或 60？
- 这是业务规则，还是临时测试值？

这时，适当的注释就能提供关键背景。

## 单行注释

最常见的注释形式是单行注释，使用 `//`：

```rust
fn main() {
    // 用户初始积分
    let score = 0;
    println!("score = {}", score);
}
```

单行注释适合：

- 给某一行代码补充说明
- 标记某一步操作的目的
- 临时屏蔽少量代码

## 多行注释

如果说明内容比较长，可以使用多行注释 `/* ... */`：

```rust
/* 这是一个多行注释。
   当说明内容比较长时，
   用这种形式会更方便。 */
fn main() {}
```

不过在实际开发中，多行注释并不一定比连续多行 `//` 更常用。很多团队更偏向使用连续单行注释，因为它更清晰，也更便于逐行调整。

## 文档注释

Rust 还有一种更有价值的注释，叫做文档注释。它通常用于函数、结构体、枚举、模块等对外提供的接口说明。

函数文档注释示例：

```rust
/// 计算两个整数的和
fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

模块或文件级别的文档注释还经常使用 `//!`，用来说明当前模块整体的用途。随着后面章节深入，你会越来越频繁地见到这种写法。

文档注释和普通注释的区别在于：

- 普通注释主要是给阅读源码的人看。
- 文档注释除了给人看，还能参与生成项目文档。

这也是 Rust 生态里文档质量普遍较高的一个重要原因。

## 什么样的注释才有价值

最常见的低质量注释，是“把代码重新说一遍”。

例如：

```rust
// 把 1 赋值给 x
let x = 1;
```

这种注释几乎没有信息量，因为读代码的人本来就能看懂。好的注释应该尽量解释下面几类信息：

- 这段代码为什么要这样写
- 这里处理的是哪一条业务规则
- 这个写法避开了什么坑
- 某个看似奇怪的数字或判断条件来自哪里

也就是说，注释最该补充的是“意图”和“背景”，而不是机械重复语法。

## 注释不是越多越好

注释很重要，但不是越多越专业。如果一段代码本身已经足够清晰，还硬要塞满解释，反而会增加阅读负担。

更好的做法通常是：

- 先把代码写清楚
- 再用必要的注释补充原因、边界和约束

如果一段代码必须靠大段注释才能看懂，很多时候说明代码本身就应该继续重构。

## 本节小结

注释的目的不是装饰代码，而是帮助后来的人更快理解程序。普通注释用于局部说明，文档注释用于接口说明。写注释时最值得记住的一条原则是：解释“为什么”，少重复“做了什么”。

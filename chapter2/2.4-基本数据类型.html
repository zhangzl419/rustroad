2.4 基本数据类型

2.4 基本数据类型

程序处理数据，首先要知道“数据是什么”。数字、真假、字符、成组的数据，它们的性质都不一样，编程语言必须有办法把这些差别表示出来，这就是数据类型的作用。

Rust 是静态类型语言。所谓静态类型，简单说就是：变量的类型在编译阶段就要确定下来，编译器会据此检查各种操作是否合法。这样会让很多错误在程序运行之前就被发现。

类型推断和显式标注

Rust 虽然是静态类型语言，但并不意味着你必须在每个地方都手动写类型。编译器通常可以根据上下文推断：

fn main() {
    let x = 10;
    let y = 3.14;
}

这里 x 会被推断为整数类型，y 会被推断为浮点数类型。

当上下文不够明确，或者你想让含义更清楚时，也可以显式写出类型：

fn main() {
    let count: i32 = 10;
    let price: f64 = 3.14;
}

标量类型

Rust 的基本类型可以先分成两大类：标量类型和复合类型。

标量类型表示单个值，主要包括：

  • 整数
  • 浮点数
  • 布尔值
  • 字符

整数类型

整数类型分为有符号和无符号两类：

  • i8、i16、i32、i64、i128
  • u8、u16、u32、u64、u128

其中：

  • i 表示 signed，也就是有符号整数，可以表示正数和负数。
  • u 表示 unsigned，也就是无符号整数，只表示 0 和正数。

最常见的整数类型是 i32，很多示例里都会优先使用它。

fn main() {
    let a: i32 = -10;
    let b: u32 = 20;
    println!("a = {}, b = {}", a, b);
}

Rust 还提供 isize 和 usize，它们的长度和当前平台指针宽度相关，常用于索引、长度等场景。后面处理集合时你会经常遇到 usize。

浮点数类型

Rust 的浮点数主要有两种：

  • f32
  • f64

其中 f64 精度更高，也是默认使用的浮点类型。

fn main() {
    let x = 2.0;      // 默认是 f64
    let y: f32 = 3.5; // 显式指定为 f32
    println!("x = {}, y = {}", x, y);
}

布尔类型

布尔类型只有两个值：true 和 false。

fn main() {
    let is_rust_fun: bool = true;
    println!("{}", is_rust_fun);
}

布尔值通常来自比较运算或者条件判断，是控制程序流程的重要基础。

字符类型

Rust 使用 char 表示单个字符，写法使用单引号：

fn main() {
    let c: char = 'R';
    let heart: char = '心';
    println!("{} {}", c, heart);
}

这里要特别注意，char 表示的是一个 Unicode 标量值，不只是 ASCII 字符。因此 Rust 的字符类型比很多人直觉里想象的更“宽”。

复合类型

复合类型可以把多个值组合到一起。当前最常见的有两种：

  • 元组（tuple）
  • 数组（array）

元组

元组可以把多个不同类型的值放在一起：

fn main() {
    let tup: (i32, f64, char) = (100, 6.4, 'A');
    println!("{}, {}, {}", tup.0, tup.1, tup.2);
}

元组的特点是：

  • 可以包含不同类型的数据
  • 长度固定
  • 使用点号加位置访问元素，例如 tup.0

元组适合表示“一组相关但类型不同”的值。

数组

数组中的所有元素必须类型相同，而且长度固定：

fn main() {
    let numbers: [i32; 3] = [1, 2, 3];
    println!("{}", numbers[0]);
}

这里 [i32; 3] 的意思是：“一个长度为 3、元素类型为 i32 的数组”。

数组适合表示“数量固定、元素类型相同”的一组数据，例如一周 7 天的固定安排、RGB 三个颜色通道等。

元组和数组的区别

这两个类型都能“放多个值”，但使用场景不同：

  • 元组强调不同类型数据的组合
  • 数组强调相同类型数据的成组存放

例如，一个学生的“编号、成绩、等级”更适合用元组；一组考试分数更适合用数组。

初学者常见误区

1. 以为类型写不写都一样

Rust 会帮你做很多类型推断，但这不等于类型不重要。恰恰相反，Rust 是因为非常重视类型，才会在编译阶段严格检查它们。

2. 把 char 当成“一个字节”

在 Rust 里，char 表示一个 Unicode 字符，不是简单的单字节概念。这个区别后面处理字符串时会很重要。

3. 把数组当成可随意增减长度的容器

Rust 数组的长度是固定的。后面你会学到 Vec<T>，那才是更常用的可增长集合。

本节小结

理解数据类型，不只是为了记住几个名字，更是为了让你在写代码时能准确回答一个问题：这个值到底是什么，它应该用什么形式来表示。Rust 的类型系统会在这件事上不断要求你“说清楚”，这正是它可靠的重要原因。

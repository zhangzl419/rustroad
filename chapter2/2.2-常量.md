# 2.2 常量

上一节讲的是变量。变量的特点是“名字绑定到一个值”，而且这个值在某些情况下可以变化。常量则更严格：它从定义开始，就不应该改变。

常量常用于表示那些在程序运行期间始终固定的量，例如：

- 程序允许的最大重试次数
- 一些固定的数学参数
- 协议中的默认端口或固定限制

## 常量的定义方式

Rust 使用 `const` 定义常量：

```rust
const MAX_POINTS: u32 = 100_000;

fn main() {
    println!("MAX_POINTS = {}", MAX_POINTS);
}
```

从这个例子里可以看出，常量有两个明显特征：

- 必须使用 `const` 关键字。
- 必须显式标注类型。

与很多 `let` 变量不同，常量不能完全依赖编译器自动推断类型。这样设计是为了让常量的含义更明确，也便于它在更大范围内被使用。

## 常量和不可变变量的区别

初学者最容易产生的误解是：既然变量默认不可变，那常量和不可变变量是不是差不多？

表面上看很像，但它们的定位并不相同。

先看不可变变量：

```rust
fn main() {
    let x = 10;
    println!("{}", x);
}
```

再看常量：

```rust
const LIMIT: i32 = 10;

fn main() {
    println!("{}", LIMIT);
}
```

它们的差别主要体现在下面几个方面：

### 1. 定义关键字不同

- 不可变变量使用 `let`
- 常量使用 `const`

### 2. 类型要求不同

- 不可变变量通常可以依靠类型推断
- 常量必须显式写出类型

### 3. 适用场景不同

- 不可变变量更适合某个局部范围内“暂时不变”的值
- 常量更适合整个程序中“本来就应该固定”的值

### 4. 求值时机不同

常量要求在编译时就能够确定。也就是说，`const` 后面的值必须是编译器能够直接算出来的内容，而不能依赖运行期才知道的结果。

例如，下面这种写法就是不成立的思路：

```rust
// 这里只是示意：运行时得到的值不能直接拿来定义 const
// const SIZE: usize = get_size();
```

因为 `get_size()` 如果依赖运行期计算，编译器在编译阶段就无法得到它的值。

## 常量的命名习惯

Rust 社区通常使用全大写加下划线的方式命名常量：

```rust
const MAX_RETRY_TIMES: u8 = 3;
const DEFAULT_PORT: u16 = 8080;
```

这不是语法强制要求，但它是一种非常普遍的代码风格。这样一眼就能看出某个名字代表的是常量。

## 常量适合放在哪里

常量往往定义在比较靠外层的位置，供多个函数共享使用。例如：

```rust
const SECONDS_PER_MINUTE: u32 = 60;

fn print_seconds(minutes: u32) {
    println!("{}", minutes * SECONDS_PER_MINUTE);
}
```

这样做的好处是，一旦规则需要调整，只改一个地方即可，而不是到处查找硬编码的数字。

## 不要把所有固定值都写成常量

虽然常量很有用，但也不要走到另一个极端。不是所有数字都值得抽成常量。

例如，下面这种写法未必更清晰：

```rust
const TWO: i32 = 2;
let result = 10 / TWO;
```

这里的 `2` 本身就足够直观，抽成常量反而可能让代码变得啰嗦。常量真正适合的是那些“有业务含义”或者“将来可能统一调整”的值。

## 本节小结

常量和不可变变量都体现了“值不变化”的特征，但两者不是同一个概念。不可变变量更偏向局部使用，常量更偏向全局规则和固定配置。理解这层差别，写代码时才不会一股脑把所有东西都写成 `const`。

# 2.1 变量和可变性

变量是程序中保存数据的最基本方式。无论是用户输入、计算结果，还是某个临时状态，本质上都需要通过变量来表示。

在很多编程语言里，变量默认就是“可以修改”的；但在 Rust 中，变量默认是不可变的。这个设计一开始会让人有点不习惯，但它恰恰体现了 Rust 的思路：如果一个值本来就不该被修改，那就不要给它“被随意改动”的机会。

## 变量的基本定义

Rust 使用 `let` 定义变量：

```rust
fn main() {
    let x = 5;
    println!("x = {}", x);
}
```

这里的 `x` 被绑定到了整数值 `5`。在这个例子中，Rust 会自动推断 `x` 的类型，因此不需要手动写成 `let x: i32 = 5;`。

需要注意的是，这里的 `x` 默认是不可变变量，也就是说，后面不能直接给它重新赋值。

```rust
fn main() {
    let x = 5;
    x = 6; // 编译错误
}
```

这不是 Rust 在“故意限制你”，而是 Rust 希望你先明确表达意图：这个值到底是不是应该变化。

## 为什么默认不可变

默认不可变有几个直接好处：

- 代码更容易理解。看到一个不可变变量时，你可以放心地认为它在后续不会突然变成别的值。
- 编译器更容易帮助你发现问题。很多意外修改、状态混乱的问题，会在编译阶段就暴露出来。
- 更符合 Rust 强调安全和可预测性的整体设计风格。

换句话说，Rust 不是不允许修改数据，而是要求你在“需要修改”的时候明确写出来。

## 可变变量和 `mut`

如果某个变量确实需要被修改，就要在定义时加上 `mut`：

```rust
fn main() {
    let mut count = 0;
    println!("count = {}", count);

    count = count + 1;
    println!("count = {}", count);
}
```

`mut` 的意思很直接：这个变量是可变的。这样写以后，后续重新赋值就是合法的吗。

不过，`mut` 不应该被滥用。初学时容易形成一种习惯，只要不确定，就先把变量写成可变。这样虽然“省事”，但会让代码越来越难维护。更好的做法是：

- 默认先写不可变变量。
- 只有在确实需要修改时，再加 `mut`。

## 变量遮蔽

Rust 中还有一个和“修改变量”很像、但本质不同的机制，叫做变量遮蔽（shadowing）。

```rust
fn main() {
    let x = 5;
    let x = x + 1;
    let x = x * 2;

    println!("x = {}", x);
}
```

运行结果是：

```text
x = 12
```

这段代码看上去像是在反复修改 `x`，但实际上不是。每一行 `let x = ...` 都是在定义一个新的变量，只是新变量和旧变量重名，新变量把旧变量“遮住”了。

变量遮蔽和 `mut` 的区别非常重要：

- `mut` 是同一个变量被重新赋值。
- 遮蔽是定义了一个新的同名变量。

## 遮蔽有什么用

遮蔽最大的价值，是它可以在保持变量名一致的同时，分阶段整理数据。

例如，用户输入的内容一开始可能是字符串，处理之后变成数字：

```rust
fn main() {
    let spaces = "   ";
    let spaces = spaces.len();

    println!("spaces = {}", spaces);
}
```

第一行的 `spaces` 是字符串切片，第二行的 `spaces` 是整数。这里如果使用 `mut`，就做不到这种“类型变化”；但用遮蔽就可以。

所以，遮蔽常用于下面这些场景：

- 对原始数据做一轮清洗或转换。
- 希望在逻辑上沿用同一个名字，但值已经进入下一个阶段。
- 想保持变量不可变，同时又需要得到新的计算结果。

## 一个容易混淆的点

下面两段代码看起来相似，但意义不同。

第一段使用 `mut`：

```rust
fn main() {
    let mut value = 10;
    value = 20;
    println!("{}", value);
}
```

第二段使用遮蔽：

```rust
fn main() {
    let value = 10;
    let value = 20;
    println!("{}", value);
}
```

它们都能得到 `20`，但第一段强调“这个变量会变化”，第二段强调“这是一个新的阶段结果”。从写法上看区别不大，从代码含义上看区别很大。

## 本节小结

这一节最重要的不是记住 `let` 和 `mut` 两个关键字，而是理解 Rust 的态度：默认认为数据不该被随意改动，只有在确实需要变化时，才显式允许变化。这个思路会在后面的所有权和借用中继续体现出来。
